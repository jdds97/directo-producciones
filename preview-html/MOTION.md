`prefers-reduced-motion: reduce`: no se crean animaciones WAAPI del hero; opacity 1 y transform none desde el inicio; transiciones CSS desactivadas; menú abre/cierra inmediatamente, conservando foco, `inert` y controles. Si cambia la preferencia durante la reproducción, se cancelan las animaciones del hero. No se oculta contenido para revelar al hacer scroll.

Verificado en Chrome real (prototipo local): estados hero a 0/320/640 ms, valores interpolados y final; menú abrir/cerrar/Escape/foco y reduced-motion. Evidencia `evidence/verification.json`, `motion-*.png`, `mobile-menu.png`, `reduced-motion.png`. Esto verifica el prototipo local; no equivale a playback nativo Figma.

Contraste mínimo del CTA durante la entrada, .84 de opacidad sobre blanco: 5.93:1. Combinaciones finales de texto ≥5.39:1. Líneas translúcidas del gráfico son decorativas y no llevan información exclusiva.

Integración futura Astro: conservar CSS para estados y WAAPI para la entrada/menu; comprobar la media query antes de animar. Render SSR deja todo visible, mejora progresiva; si JS falla no falta ninguna sección. Cerrar menú debe cancelar una transición anterior y restaurar foco una sola vez. No añadir librerías sin necesidad demostrada. Sin reflow, parallax, scroll hijacking, flashes ni bucles infinitos.

Ampliación verificada: `evidence/suite-interactions.json` cubre ambos temas, menú con/sin reduced-motion, foco, Escape, inert y formulario sin envío. La preferencia de motion cambiada durante el hero oscuro cancela las animaciones y deja todo visible. Suite: flecha SVG de CTA/enlace tiene el mismo feedback que Inicio claro. La guía documenta botones, campos y errores; no se presenta como reproducción nativa.
